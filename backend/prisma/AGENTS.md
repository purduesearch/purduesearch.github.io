# AGENTS.md — Database Schema (`backend/prisma/`)

Scope: Prisma schema, models, and enums. Applies together with the root and
`backend/AGENTS.md`.

---

### Database (`backend/prisma/schema.prisma`)
Key models include `Member`, `Project`, `ProjectMember`, `Task`, `TaskComment`, `TaskDependency`, `Blocker`, `TaskBlocker`, `Milestone`, `TimeLog`, `Activity`, `ActivityLog`, `GitHubLink`, `ProjectRepo`, `Event`, `OutreachSubmission`, `BlogPost`, `Course`, `CourseModule`, `CourseSection`, `CourseWorkSubmission`, `Training`, `TrainingCertificate`, `XpEvent`, `DoubloonEvent`, `Challenge`, `MemberChallenge`, `MemberAchievement`, `Cosmetic`, `MemberCosmetic`, `MemberInventory`, `SlackMessage`, `SlackMessageFile`, `SlackConversationMember`, `Workspace`, `WorkspaceProject`, `WorkspaceRequirement`, `LabShift`, `LabShiftSkip`, `VaultDrawingRequirement`, `VaultRelease`, and the Phase 8 `VaultSubscription`, `VaultNotificationEvent`, `VaultNotificationDelivery`, `VaultSearchDoc`, and `VaultSavedView`, and the Phase 9 `VaultGeometryDiff` (cache row unique per `projectId` + `cacheKey`; `resultJson` TEXT, derived and prunable). `VaultSearchDoc.searchVector` is `Unsupported("tsvector")` with a GIN index; only the raw upsert in `vaultSearchService.ts` writes it, and after a deploy that adds or changes index documents run `npm run vault:search-rebuild`. `VaultNotificationDelivery`'s `@@unique([eventId, recipientId, channel])` is the deduplication guarantee — never drop it. `VaultRelease.manifestJson` is immutable TEXT (not JSONB, which reorders keys) hashed into `manifestSha256`; only the `package*`/`leaseUntil` columns change after the approval transaction inserts it. `VaultItem.drawingForId` marks a drawing item. `Project.parentId` (self-relation, `onDelete: Restrict`, one level enforced by the API) groups sub-projects; `ProjectMember.addedManually` marks admin-added members outside the Slack channel; `ProjectMember.isLead` (admin-set) is the project-lead flag; `projectRole` is a free-text title that Slack channel sync resets to `Contributor`, so never derive permissions from it. `LabShift` dates are `@db.Date` local dates and minutes are local; `Event.workspaceId` links an event to a lab space (SetNull). Search the schema for the authoritative fields and relations before writing queries; there is no `MilestoneTask` or `InventoryItem` model in the current schema.
The Slack mirror models are `SlackCardQueue`, `SlackCardMessage`, `SlackCardRef`, `SlackItemLink`, and `SlackPlanSession`; `SlackItemLink` rows are member-visible backlinks; list them only through `slackItemLinkService.listBacklinks`, which applies conversation access.

Key enums:
- `Rank` — NESTLING → FLEDGLING → CADET → SPECIALIST → PIONEER → COSMONAUT → CELESTIAL (thresholds 0–21,000 XP)
- `TaskStatus` — TODO, IN_PROGRESS, BLOCKED, DONE
- `Priority` — LOW, MEDIUM, HIGH, CRITICAL
- `RewardEventType` — TIME_LOG_HOUR, TASK_COMPLETE_MEMBER_CREATED, TASK_COMPLETE_ADMIN_CREATED, MILESTONE_HIT, KUDOS_RECEIVED, BLOG_POST_PUBLISHED, EARLY_DELIVERY_BONUS, MEETING_AVAILABILITY_SUBMITTED, COURSE_SECTION_COMPLETE, COURSE_COMPLETE
- `ChallengeMetric` — TASK_COMPLETED, COMMENT_WRITTEN, TIME_LOG_HOURS, UNIQUE_ASSIGNEES, FILE_ATTACHED, etc.
- `ChallengeType` — DAILY, WEEKLY, MONTHLY, ACHIEVEMENT
- `CourseSectionKind` — CONTENT, VIDEO, QUIZ, SLIDES, WALKTHROUGH, LIT_REVIEW, ASSIGNMENT, TRAINING. One `Json?` config column per configurable kind on `CourseSection`; **every writer spreads the previous value and writes the column whole**, never key-by-key. `LIT_REVIEW` and `ASSIGNMENT` both write learner attempts to `CourseWorkSubmission` — one model, `@@map`'d to the original `CourseLitSubmission` table so the rename emitted no DDL. One row **per attempt**, never updated in place; revision history is the point. Opt-in score gating on either kind reuses `CourseSection.passThreshold`. `TRAINING` uses the training registry/certificate models and an externally hosted course.
- `ActivityEventType` — `ActivityLog` event types (see `logAuditEvent`/`getProjectAuditLog`/`getTaskAuditLog`). Task/project/GitHub lifecycle values (`TASK_CREATED`, `TASK_UPDATED`, `TASK_COMPLETED`, `TASK_DELETED`, `TASK_ASSIGNED`, `GITHUB_PR_MERGED`, etc.) plus the audit-sync additions: `TASK_DEPENDENCY_ADDED`/`TASK_DEPENDENCY_REMOVED`, `TASK_BLOCKER_ATTACHED`/`TASK_BLOCKER_DETACHED`, `BLOCKER_RESOLVED`, `COMMENT_ADDED`/`COMMENT_EDITED`/`COMMENT_DELETED`, `TIME_LOGGED`, `MILESTONE_CREATED`/`MILESTONE_UPDATED`/`MILESTONE_DELETED`/`MILESTONE_TASKS_LINKED`, and `AI_PLAN_EXECUTED` (one summary event per AI action-plan execution, in addition to the specific event type logged per executed action).

Member XP lives in **two places kept in sync by `grantXP()`**: a `Member.xp` running-total column (read for display/rank) and `XpEvent` ledger rows (audit/history). Never increment one without the other — go through `rewardService.grantXP()`.
Task `rewardGrantedAt` is an idempotency gate; do not clear it or DONE→IN_PROGRESS→DONE re-grants XP.
Skills models (migration `20261013120000_skills`): `Skill`, `SkillAlias` (`aliasNorm` unique across the taxonomy), `SkillEdge` (PARENT/RELATED/PREREQUISITE), `SkillProposal`, `SkillSuppression`, `SkillEvidence` (+ `SkillEvidenceSkill` join, which scoring reads — `skillIds` is "as analysed"), `SkillAssessment` (unique on member, skill, provenance, `assertedById`; `assertedById` is `""` for `AI_INFERRED` so the key has no NULLs), `SkillDispute`, `SkillVisibility`, `SkillProjectVisibility`, `MemberPortfolio` (`enabled` defaults to false; `showOnProfile` defaults to true and controls the teammate view), `SkillRun` (`progress` JSON while RUNNING, `cancelRequested`; migration `20261015120000_skills_upgrade`, which also adds `SkillProposal.evidenceIds`). **`SkillEvidence` is append-only**: a Postgres trigger rejects UPDATE of anything except `supersededAt` and `embedding`; DELETE stays allowed so removing a Member cascades. `contentHash` stores `<hash>@<promptVersion>` so a prompt bump re-analyses without breaking the unique key. `SkillEvidence.projectId` has no FK on purpose (history outlives projects). Edit the migration SQL by hand only before it is applied anywhere.
